The safest reproduction of the completed study is an audit of immutable evidence, not a fresh scientific rerun. The frozen terminal outcome is PHK_V21_ORACLE_NO_GO_STOP_BEFORE_PINN.

The decisive terminal summary is [summary.json](../outputs/runs/20260828T-phk-v21-s1-q-terminal-summary-001/summary.json).

## 1. Environment

The production S1 qualification used a Windows host, Python 3.11.9, the project virtual environment, float64 numerical calculations, and local CPU only. No CUDA/GPU, paid compute, or cloud compute was used.

The final figures were generated separately with local Python 3.12 and Matplotlib 3.8.4. Figure generation reads only existing evidence and performs no scientific solve.

## 9. Why the production qualification is not rerun here

S1 run IDs and output directories are immutable. The complete ladder consumed 1.128515625 CPU core-hours and reached a terminal No-Go. Reusing those IDs would violate evidence identity; silently changing the contract would create a different study.

A fresh numerical rerun requires a new explicit research authorization, a prospective contract or exact-replication identity, fresh run IDs and a fresh experiment root or valid supersession chain, and preservation of the existing PHK-V2.1 result. This guide therefore does not instruct the reader to rerun the production ladder in place.

## 10. Reproduction boundary

Successful hash checks, tests, figure regeneration, or package validation establish traceability and implementation reproducibility. They do not change the scientific claim ceiling and do not turn the candidate floor into an admissible neural floor. Code availability does not establish material calibration, experimental validation, PINN performance, or formal OOD generalization.
