# PHK-V2.3 LF9 AutoDL deployment

LF9 deploys only the activation commit and seven hash-bound inputs: the medium
carrier used for no-gradient competence audits, the exact LF6 DEV-R checkpoint,
the LF6 pre-materialized strong-physics ledger and manifest, the LF9
pre-materialized control-volume ledger and manifest, and the passed zero-update
LF9 CPU qualification. The bundle never archives unrelated working-tree files.

The remote preflight verifies activation-commit bytes, aggregate bundle
identity, every input binding, the complete strong and control-volume ledgers,
the training/blind split, the exact V100 identity, an empty campaign output
root, absence of reference-only assets, and absence of duplicate LF9 processes.
Runtime generation of strong collocation points or control-volume patches is
forbidden.

One core process owns the frozen scientific order:

1. mandatory equation-routed strong-form screen (`ER-S`);
2. mandatory equation-routed thermal-control-volume screen (`ER-CV`), even if
   the other screen has an arm-local failure;
3. conditional continuation of the selected screen endpoint;
4. conditional matched no-filter control only after the selected filtered path
   passes the reference-blind prelocal internal Pareto gate. The complete PINN
   Pareto adjudication remains pending until post-shutdown local evaluation.

Medium data are used only for no-gradient filter audits. Fine, extra-fine,
direct LF_ONLY, local evaluators, and stress/OOD references are forbidden on
the cloud. After the process exits, recover and hash the configured artifacts,
verify zero training and GPU compute processes, and shut the instance down
before local adjudication.

The operator supplies `LF9_SOURCE_IDENTITY`, `LF9_DEPLOYMENT_ROOT`,
`LF9_CPU_QUALIFICATION`, and an empty absolute `LF9_OUTPUT_ROOT` under
`/root/autodl-tmp/` whose basename begins with `lf9-run-`.
