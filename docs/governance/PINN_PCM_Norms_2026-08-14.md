# 项目研究背景、研究偏好、规范与指令约束

## 一、项目研究背景

项目位于物理信息神经网络（PINN）、氧化物相变材料、相变器件/忆阻器/热神经元、光电信息与神经形态计算的交叉区域。当前不依赖自有流片、原位显微表征或成套硬件平台，而是纯软件闭环。以一个月内完成从 idea 生成到形成二区SCI水准的论文初稿为目标；GPU 可租用，但不得进行无界超参数搜索、重复救援或缺乏停止条件的长期数值试错。

## 二、适用范围、规则等级与冲突处理

本文件用于约束本项目的选题、建模、方法设计、代码实现、数值实验、证据解释、论文写作、仓库协作与交付。除非另有更具体且经用户确认的合同，本文件作为项目级默认权威规范。

规则标签含义如下：

- **[硬约束]**：除非用户明确修改，否则不得违反。
- **[默认偏好]**：用于提高研究与交付效率，持续影响选题、资源配置与论文主要方法模块。可由当前执行的任务中更具体的规则覆盖、调整，或由用户决定是否修改。
- **[阶段性约束]**：仅绑定指定阶段、实验或当前时间窗口，执行前须核验实时状态。
- **[阶段性事实]**：已形成或已确认的项目状态，可被后续证据更新，但不得追溯性篡改。

## 三、资源边界与总体目标

1. **[硬约束] 不得静默调和实质冲突。** 若两条规则冲突明显，应暂停，交由用户决定。
2. **[默认偏好] 每项工作必须具有明确的论文去向。** 开始前说明服务于哪一条论文主张、方程、主图或表、消融、泛化结果、局限性、审稿问题、复现项或投稿材料；不能进入证据链或论文链的工作默认不做。
3. **[硬约束] 论文定位。** 以中科院二区 SCI 为主要目标，最低形成三区以上水平、可审稿、证据闭合且符合学术规范的论文初稿，并逐步形成补充材料、投稿包与答审材料；这是交付目标，不是期刊接收承诺。
4. **[硬约束] 主题目标。** 始终围绕“PINN 与相变材料/相变器件结合”；正面方法论文中，PINN 必须是核心方法，算法或网络架构必须具有可测量的实质创新。
5. **[默认偏好] 物理目标。** 不得以抽象方域、一维模型或单节点模型充当论文主体。
6. **[默认偏好] 应用目标。** 在真实器件结构上证明实用性和泛化性能；证据允许时可探索参数反演、缺陷诊断、不确定性或拒判，但反问题必须先满足可辨识性要求。
7. **[硬约束] 工程目标。** 形成可复现的代码、配置、数据、图表和证据映射，使研究结果能够直接进入论文与补充材料。

## 四、PINN 身份、物理模型与方法边界

8. **[硬约束] PINN 命名须与实际损失一致。** 只有损失函数含有明确且有文档记录的 PDE 或本构残差时，方法才可称为 PINN；仅含投影、循环一致性或其他物理约束的方法，应准确称为物理约束或物理嵌入的混合反演网络。
9. **[硬约束] PINN 不得名义化或装饰化。** 在正面方法路线中，PINN 必须承担核心求解、代理、反演或物理约束功能，传统求解器不能替代其核心贡献。
10. **[硬约束] 算法或网络复杂度只是贡献候选。** 更复杂的架构、训练算法或控制流只有实现相对强基线的增量时才构成创新；仅增加层数、更换复杂名称不构成新路线。
11. **[硬约束] 保持纯软件、多物理场路线。** 传统求解器不得冒充实验数据，也不得在正面方法论文中取代 PINN 核心贡献。
12. **[硬约束] 多物理模型至少闭合电—热—相态因果链。** 每次增加相场、离子输运、光学或电路动态等模块，都必须说明物理必要性、接口和可检验增量；非必要模块不进入主路线。
13. **[默认偏好] 实用性和泛化性须严格留出测试证明。** 训练域内插值、同一轨迹的相邻点或单个展示 case 不能替代几何、器件、协议或其他真实实体上的 formal OOD。
14. **[默认偏好] 反问题先做可辨识性分析。** 至少检查 Jacobian/SVD、profile、有限扰动、近零空间、观测充分性；不可辨识时不得用神经网络掩盖问题。

## 五、Idea 生成、模块迁移、“魔改”与排列组合

15. **[默认偏好] 采用“合规迁移/魔改＋排列组合”生成候选方案。** 先把可靠文献方法/idea拆成可解释模块，再做定向适配，并在明确接口、前提和证据边界内组合。
16. **[默认偏好] 完整记录来源模块。** 对每个模块记录原问题、核心机制、输入输出、控制流、适用假设、数据要求、来源、可复用接口与预期能力。
17. **[硬约束] 区分直接迁移与适配。** 用 A 表示有来源的直接迁移模块，用 A′ 表示有文档记录的适配模块；对每个撇号准确说明改了什么、为什么改、影响哪个接口、预期产生什么能力，不得用新名字掩盖旧方法。
18. **[硬约束] 允许直接迁移，但必须透明归因。** 组合价值不要求每个组件都原创或都经过修改；直接迁移的组件同样必须记录来源与许可，不能复制后冒充原创。
19. **[默认偏好] 魔改可发生在多个层面。** 包括物理变量、材料机理、真实几何、边界/界面、网络输入输出、残差/损失、训练控制流、采样、协议与历史编码、求解器耦合、不确定性/拒判、评价指标或证据合同。
20. **[默认偏好] 排列组合可跨越多个模块层。** 包括物理底座、数值求解器、表示网络、刚性处理、可观测子空间、协议设计、反演器、不确定性/集合输出、保守投影和验证流程。
21. **[硬约束] 候选池要广而有界。** 先生成足以覆盖高价值方向的候选池再剪枝；不得枚举无界幂集或为填表制造候选。
22. **[硬约束] 新组合必须包含实质变化。** 至少在物理前提、模块接口、研究任务或可检验主张中有一项实质改变。
23. **[默认偏好] 贡献来源可以多元，但不得替代核心要求。** 问题驱动适配、接口闭合、工作流、功能组合、验证合同、适用域、可组合性、保守性、拒判能力或新物理诊断能力均可形成贡献；在正面方法论文中，这些贡献不能替代算法或网络架构的实质创新要求。
24. **[默认偏好] 分开记录模块来源、贡献类型和证据强度。** 组件已有先例不等于组合主张无效，组合看似新颖也不等于证据已经成立。
25. **[默认偏好] 逐层装配复杂方法。**不一次堆满所有高级模块，以保持失败可解释、消融有效。
26. **[硬约束] 负面结果仅按证据边界使用。** 有边界的局限性或负面结果可用于收尾、补充材料和审稿防御，但不得用零新增证据的快速负面稿自动替代高价值研究目标，不得制造正向结果，也不得暗中重开已停止路线。

## 六、数据、数值实验、基线与评价规范

27. **[默认偏好] 先做小 case sanity check，再启动昂贵训练。** 优先验证方程、单位、边界、守恒、数量级、数据接口和数值稳定性；通过最小门槛后再扩展规模。
28. **[硬约束] 严格区分数据与证据身份。** 项目合成数值、文献证据、研究事实必须分别标识，不得相互冒充或替代。
29. **[硬约束] 按完整物理 case 或真实实体划分数据。** 训练、验证和测试集应按器件、几何、协议、轨迹、时间窗或其他真实实体划分；不得拆散同一轨迹/几何/协议的相邻点制造虚假泛化。
30. **[硬约束] 建立防泄漏边界。** 测试集信息、真实参数、测试专属基底及 formal OOD 不得进入训练、部署输入、阈值确定或超参数选择。
31. **[默认偏好] 每个 PINN 方案必须比较最强直接基线。** 视任务至少纳入解析模型、ridge/低秩模型、独立 solver、纯数据网络或已知强 PINN 基线中的相关者。
32. **[默认偏好] 最小 headline 比较采用“三件套”。** 正式扩展前至少比较最强直接基线、一个能够隔离关键模块/接口的消融和完整组合；idea/MVP 阶段不要求对所有排列组合做全量消融，只有主结论需要时才扩展。
33. **[硬约束] 不要求完整组合在每个指标上击败所有基线，但必须证明预声明增量。** 若某指标落后，应检查预先声明的功能、接口、稳定性、守恒、速度、鲁棒性、适用域、验证、可组合性或可复用负面增量；若均不存在，应判定组合增量证据不足。
34. **[默认偏好] “网络参与计算”不等于 neural-specific value。** 正面贡献必须证明相对解析、ridge、POD、传统 solver 或纯数据基线的独立增量。
35. **[硬约束] 项目研究事实与科学事实分开。** 代码存在、测试通过或文件生成只能证明实现/执行状态，不能证明科学主张。
36. **[硬约束] 测试真实行为与真实产物。** 高风险主张须严格核对实际运行、实际研究成果、数值有效性与有效证据，不能凭代码或文档“看起来完成”判定成功。
37. **[默认偏好] 基础执行环境统一。** 使用 Python 3.11、项目虚拟环境和可在 CPU 上运行的冒烟测试；GPU 用于通过最小门槛后的高价值训练或数值实验。

## 七、证据解释、主张边界与止损规则

38. **[硬约束] 区分已验证事实、证据支持的解释、假设/猜测与未知。** 不得用自信措辞或流畅叙事填补证据空白；未核验内容需明确标注。
39. **[硬约束] 保持批判性，不迎合预设结论。** 若结果不支持 PINN 优势、二区创新性或预期物理故事，应直接指出失败的研究项、可保留成果和解决方案。
40. **[硬约束] 不掩饰负结果。** 不用“仍有潜力”等模糊措辞稀释失败，保留其适用边界、可复用资产及对后续研究路线的启发。
41. **[硬约束] 每条强结论须路由到证据。** 论文主张应能映射到原始文献/仓库实现/配置/数据/运行产物/图表或统计结果中的相应证据。

## 八、文献、来源、许可与学术道德

42. **[硬约束] 来源优先级固定。** 原始论文、官方补充材料、公开源数据、作者代码和权威数据库优先于权威综述；权威综述优先于搜索摘要；内部报告、历史会话和 AI 生成内容只能用于线索、设计和历史解释。
43. **[硬约束] 保存文献与外来资产。** 记录 DOI、版本、许可、页码、图号、方程号、数据获取方式、适用边界，以及外来模块是直接迁移还是适配；文献启发、工程先验须分别标识。
44. **[硬约束] 内部材料不能单独支撑外部科学事实。**头脑风暴和深度调研结果、内部报告、AI 内容和历史会话的结论进入论文前，必须由原始文献或仓库证据核验。
45. **[硬约束] 禁止抄袭、隐藏来源、复制后冒充原创或虚报优先权。** 合规借鉴不要求每个模块都彻底改写，但组合贡献必须透明且有证据边界。
46. **[硬约束] 禁止编造。** 不得编造数据、曲线、引文、许可、物理参数、实验验证、优先权或论文接受前景；证据不足时应删除或明确标注为假设。
47. **[硬约束] 不得混用材料、本构和参数层级。** 各类材料不能因数值相近而互换；器件等效参数不得冒充材料本征常数。
48. **[硬约束] 清除不可移植引用。** `cite`、`filecite` 等会话标记不得进入 Markdown 成稿、论文、补充材料或参考文献；聊天式引用占位符不得替代正式可解析引用。

## 九、计划、实施、代码与 Git 工作流

49. **[默认偏好] 先规划再执行。** 计划应具体简洁，可直接执行，不以长篇空泛规划替代研究。
50. **[默认偏好] 重大科学任务采用 PLAN → 批准 → EXECUTE。** PLAN ONLY 阶段保持只读，不试跑实验；长时间求解、训练或外部写入须先获得授权。执行阶段使用有预算、检查点和停止条件的任务，不使用可能连续运行数小时的开放式 goal。
51. **[默认偏好] 用“首张可信图时间/首条可写 claim 时间”约束方案。** 除最终理想性能外，还要估计首次获得判别性结果的真实运行负担。
52. **[默认偏好] 对轻微歧义采用最小、可逆、保守假设并记录。** 若歧义会改变模型、主张、数据边界、预算、权限、外部写入或不可逆动作，则暂停并向用户提出。
53. **[默认偏好] 代码修改保持最小且与当前主张直接相关。** 先检索现有实现、调用点、许可和聚焦测试，优先复用兼容代码；不做无关重构、全仓库格式化、异常输入大全、顺手清理或为假想未来需求增加旗标、包装层、迁移框架、平行权威、仪表盘和永久版本树。
54. **[默认偏好] 不因发现邻近问题扩张任务。** 新发现若不阻塞当前论文主张，应记录并留待后续，不自动纳入本轮。
55. **[默认偏好] 治理改动与科学改动保持可审查边界。** 同一任务确有两类必要改动时应清楚分离，避免混成无法审查的提交；不得仅为治理仪式额外创建分支、改目录。
56. **[默认偏好] 使用一个有界的执行—验证闭环。** 只有相关输入或实现变化时才重跑检查；达到预声明的通过、失败或阻塞条件后立即收口并路由结果。已明确授权的科学任务若在首个 optimizer step 前因纯工程故障终止，且没有形成科学轨迹，故障根因已明确定位并由针对性隔离回归证明完全修复，则可在相同科学身份下重新执行；此类工程重执行不消耗 exploration、confirmation 或其他科学 run 配额，并覆盖较旧合同中的工程 retry 次数限制。该覆盖不允许改变方法、物理、数据、seed、阈值、预算或科学停止条件。
57. **[硬约束] 不用机械治理指标替代判断。** 不以字节、token、行数或文件数门槛评价质量，不用装饰性评分表、机械清单、重复审计或同类评审共识制造工作量；仅在真实外部系统硬限制或用户明确批准时使用数值限制，并一次性处理。
58. **[硬约束] 防护真实可达边界。** 只防护公开接口、真实项目数据、受支持的 Windows 执行路径或实际数值模型可到达的边界，不为威胁模型外的纯构造堆叠过度防御。
59. **[硬约束] 限制哈希与指纹的使用。** 仅在保护命名的不可变证据边界、正式内容寻址合同、Git/运行身份、或可替代显著更昂贵操作且结果会改变准入、重放或下一步时使用；不得将其扩散为日常治理仪式，不得反复验证哈希。
60. **[硬约束] 在授权范围内大胆探索、保守表述。** 优先推进最高价值实验，不让防御性文档挤占研究时间；探索可以大胆，证据解释和论文措辞必须谨慎。
61. **[默认偏好] 遇到 blocker 时先止损。** 给出最小决策问题、现有证据和可选路径，不用宽泛追问把选择负担转回用户，也不擅自扩大权限或研究范围。

## 十、协作、进度汇报与表达规范

62. **[默认偏好] 合理使用子 Agent。** 仅在任务规则允许时，将具体、有界、独立且真正适合并行的子任务委派；指定一个集成负责人，避免重叠写入与重复审计，并在采纳前独立核验委派结果，不为形式感启动并行工作
63. **[默认偏好] 只汇报有决策价值的进度。** 长任务仅在出现状态变化、决定性证据、阻塞或下一步变化时更新，不逐条播报命令，不重复未变化状态。
64. **[默认偏好] 可视化只在提高理解时使用。** 解释复杂映射、依赖、分支或阶段时使用最小必要的表格、流程图、时间线或依赖图；短文本已经清楚时不添加装饰性可视化。
65. **[默认偏好] 输出简洁、直接、可执行。**报告篇幅必须简洁，只包括必要内容，重点给出进展结论、实质成果、异常根因和下一步最优先解决的问题，不用冗长治理叙事掩盖科学判断。

## 十一、交付前检查

最终交付论文、补充材料、数据包、图表或投稿材料前，至少确认：

PINN 与相变材料/相变器件主题未被替换、弱化或名义化；

实际损失满足 PINN 命名条件，算法/架构创新具有可区分的增量证据；

论文主体为二维及以上器件结构，一维/零维模型仅承担辅助角色；
