# PINN-PCM 科研文件与数据处理规范

**版本：** v1.0

**制定日期：** 2026-09-28

**适用项目：** PINN-PCM-SCI 及其已授权的本地／AutoDL 研究任务
**文档状态：** 独立成文，供后续任务引用；本次未修改项目必读入口、现行科研合同或主任务状态。

## 1. 目的与适用边界

本规范服务于“本地分析与成稿—AutoDL 计算—结果回收—保存数组复算与后续复用”的工作流，目标是保住科研证据、减少重复计算、控制临时文件积累。

总原则：**本地作为最终归档与稿件工作区，AutoDL 数据盘作为计算与复用副本；按研究价值决定保留，按核验结果决定删除。**

本规范从属于 [AGENTS.md](../../AGENTS.md)、[完整项目规范](PINN_PCM_Norms_2026-08-14.md)和用户当前明确指令。具体任务已冻结的数据隔离、保存内容、恢复合同和停止条件继续有效。发生实质冲突时，只暂停受影响操作并说明冲突，不静默改写科研合同。

本文不单独授权新科研计算、历史数据清理、实例释放、远端上传、数据公开或 Git 发布；既有任务已经授权的正常保存与回收，不因本文增加逐文件审批。此次成文不代表任何备份、清理、同步或关机已经执行。

## 2. 文件分类与保留规则

文件大小只影响存储和传输方式，不单独决定是否保留。不设置适用于所有任务的固定 MB／GB 删除线。

| 类别 | 典型内容 | 默认保存方式 | 允许清理的条件 |
|---|---|---|---|
| 科研证据 | 原始输入、参考场、完整轨迹、接受终点、原始指标、失败与不利结果 | 本地和 AutoDL 数据盘长期保存；隔离例外见第 7 节 | 不自动删除；不得因结果不利或文件大而删除 |
| 运行恢复文件 | 接受态参数、完整优化器状态、随机状态、累计计数、固定支持与运行身份 | 运行中先写远端持久目录，并在安全边界回收有效恢复点 | 新恢复点完整可用后，按本轮合同轮转冗余副本；冻结终点与必要恢复证据保留 |
| 昂贵且可复用的数值缓存 | 模型查询值、脱离计算图的导数、共同读出、残差数组、条件演化缓存 | 两端保留，避免再次启动 GPU 或重新推进 | 确认不再被复算、论文或后续研究依赖后，按批准范围处理 |
| 小型追溯资料 | 配置、运行源码身份、依赖说明、日志、终止原因、指标、索引和来源许可 | 两端保存；复用已有清单和记录 | 无追溯价值的重复调试输出可在问题闭合后清理 |
| 正式稿件与交付 | 权威 Markdown、最终 PDF／DOCX、图表、证据映射、构建入口 | 本地统一编辑构建，两端保存冻结交付 | 未冻结草稿与重复构建缓存可清理，历史正式交付保留 |
| 普通临时文件 | 排版检查图片、临时展开数组、解压暂存目录、可低成本再生缓存 | 仅在实际需要的位置短期保存 | 相应检查完成、正式产物和必要输入已保留、无活动进程依赖 |
| 传输压缩包 | 回收 ZIP、TAR.GZ、上传部署包 | 传输与核验期间保留 | 按第 5 节核验后删除冗余包 |

执行含义：

- **有追溯或复用价值的小文件，两端保存。** 不要求每个临时截图、重复日志和空目录永久双份保留。
- **大文件只要承担证据、恢复或明确复用用途，也应两端保存。** 能重新计算不等于值得重新计算。
- **大而无复用价值的临时文件，在对应阶段闭合后清理。** 用途不明时先保留，不凭文件名或大小猜测。
- 原生科研数据不得为节省空间擅自降低精度、删时间点、删变量或改变格式语义。无损压缩也不得破坏现有读取接口或来源身份。

## 3. 两端职责与目录组织

### 3.1 本地与远端职责

本地维护最终归档索引、科研代码与稿件的权威编辑来源。远端保存固定部署副本和实际运行产物；尚未回收的远端结果属于原始证据，不能因本地被指定为归档端就提前删除。

AutoDL 文件必须落在该实例已确认的持久数据目录。不得仅凭历史路径或目录名称假定其保留机制；关机、释放实例、重装和删除数据盘的影响分别核实，不承诺未经核验的平台行为。

### 3.2 最小目录约定

1. 沿用项目现有稿件、运行、证据与独立复算包的目录职责，不为执行本规范批量改名或搬迁冻结目录。
2. 两端使用相同任务／运行 ID 和相对路径；在原清单中记录两端根目录。
3. 冻结证据不覆盖；新分析输出写入对应的新结果位置。普通稿件草稿无需每次编辑都生成永久版本。
4. 不按“修改时间较新”自动覆盖冲突副本；先核对其科学身份和任务归属。
5. 不以整仓双向镜像代替有范围的传输。凭据、虚拟环境、一般下载缓存及无关工作区不进入科研归档；保留实际运行源码和依赖说明。
6. 长期复算包不能只有一份放在系统临时目录。需要归档时先复制到稳定位置并核验，保留原位置直至依赖和恢复方式确认。

同一磁盘上的硬链接或重复目录可以节省空间、方便复算，但不算独立备份。Git 中的精选文件也不代替未纳入 Git 的完整数组。

### 3.3 离线同步

AutoDL 未开启或暂不可访问时，本地新增文件先可靠保存，并在原交付清单中记录“待远端同步”。不为同步少量文稿或普通 CPU 分析结果专门启动 GPU。

下次因已授权科研需要使用实例时，在不影响当前任务和隔离合同的前提下补齐同步。待同步不等于双份完成；单份期间不得清理唯一有效副本，也不能报告“已完成双端备份”。

## 4. 每轮任务的保存与回收流程

| 时点 | 必须落实的动作 | 记录位置 |
|---|---|---|
| 运行前 | 确认合法输入、输出位置、需要长期保留的产物和可用空间；只部署允许读取的资料 | 现有配置／manifest |
| 运行中 | 结果持续写入持久目录；按原合同保存接受态与成本计数 | 现有日志／检查点 |
| 结束或中断 | 保存实际终点、配置、阶段、终止原因、累计更新和评价次数；区分正常完成、资源中断和数值失败 | 现有终局／中断记录 |
| 回收 | 优先回收恢复文件、配置和日志，再回收必要大数组与昂贵缓存；支持断点续传，保留未完成标记 | 现有回收清单 |
| 核验 | 检查需要保留的两端副本完整可读；结果按实际能力标识 | 现有核验记录 |
| 关机 | 必要回收完成后及时关闭实例，并记录实际确认结果 | 现有关机记录 |
| 清理 | 仅处理已满足删除条件的传输包和临时文件，不影响冻结证据 | 原清单中的清理条目 |

补充要求：

- 恢复点必须是已接受的状态。Adam 保存完成更新后的状态；L-BFGS 参数与优化器历史必须对应同一接受态，不把试探点保存为终点。
- 新检查点完整写出、可读并符合原恢复合同时，才替换运行指针或轮转上一恢复点；不要求保留每一步的全部检查点。
- 科研缓存只保存需要复用的数值，不长期保存整条坐标 AD 计算图。缓存字段、单位、网格／时刻和导数口径须能追溯。
- 已有保存数组足以完成后续分析时，直接复用。文件整理不构成重训、重新积分或重算网络 AD 的理由。
- 不为等待排版、本地评分或一般备份整理而保持 GPU 实例运行。
- 回收异常时，先确保远端持久目录中的产物可恢复，保存未回收清单，按当前任务的关机／异常合同处理。未确认持久性时不释放实例或删除源数据；不得把“持久保存但待回收”写成“本地回收完成”。

## 5. 压缩包与解压文件处理

### 5.1 普通传输包的默认规则

**解压成功、完整性核验通过、必要副本落实后，删除冗余传输压缩包。** 不同时长期保留无用途的压缩包、解压目录和重复展开目录。

删除前必须确认：

1. 解压过程无错误，预期文件清单一致；
2. 必要数组、检查点、配置与日志能够读取；
3. 解压位置是稳定保留目录，后续不会作为同一批临时文件被删除；
4. 所需双端副本已落实，或原合同明确允许的例外已记录且不删除唯一恢复载体；
5. 来源身份和必要元数据已保留，现有恢复／复算入口不再依赖该压缩包。

不完整下载、解压失败或缺文件时保留原包，先定位问题。回收压缩包不是有效科学数据的替代品，解压目录存在也不单独证明恢复成功。

### 5.2 不能按普通 ZIP 清理的文件

- `.npz`、`.pt`、`.docx` 等可能内部使用压缩容器，但它们是正常使用的科学或文档文件，不能因“内部是 ZIP”而解压删除。
- 第三方原始包如承担不可替代的来源或字节身份，保留一份原包；其他冗余副本在核验后可清理。
- 第三方包允许删除时，至少保留来源链接／DOI、版本或提交、原文件名、许可与必要读取说明。代码许可不能自动覆盖实验数据和出版社图片。

## 6. 核验、记录与同步冲突

核验仅用于发现会影响恢复、复算、保存或删除决定的问题，不用重复审计制造工作量。

1. 小型文本与配置核对清单、内容可读性及引用关系。
2. 大数组核对传输完整性、必要字段、形状、单位与时间／空间身份；检查点只使用项目可信来源和既有安全读取方式核验。
3. 对命名的不可变证据或跨端传输包，必要时做一次内容校验；直接复用仍适用的既有校验记录，不做日常全仓哈希。
4. 双端文件不一致时保留双方，停止对应覆盖或清理，只定位受影响数据。
5. 不为验证复制成功重新训练或运行整个科研流程；只有实际恢复能力仍存在相关未知时，才完成必要的最小检查。

优先在现有 manifest／回收记录中补充下列信息，不另建平行管理系统：

| 信息 | 最小内容 |
|---|---|
| 身份 | 任务／运行 ID、相对路径或具名数据块 |
| 用途 | 证据、恢复、昂贵缓存、交付或临时文件 |
| 位置 | 本地与远端位置；不存在或待同步如实填写 |
| 状态 | 已核验、待传输、传输未完成或隔离例外 |
| 清理依据 | 哪个保留副本和已完成检查使删除安全；实际删除结果 |

同类文件可按具名数据块记录，不要求为每个临时小文件新增独立表格。

## 7. 科学隔离与证据身份

1. 双端保存不得改变参考、留出、stress 或未来评分数据的封存要求。禁止因备份方便将其放入训练输入包或模型入口。
2. 某轮合同禁止资料进入远端环境时，按原合同保存并记录隔离例外；本文不要求突破隔离实现形式上的双份。
3. 完整主结果、比较者、负面结果和必要故障记录保留各自身份，不选择性清理。
4. 保存数组重评分、保存残差重新聚合、检查点推理及重新计算神经 AD 残差分别描述；不能用文件存在或备份完成替代相应能力验证。
5. 本地与私有计算端均有文件，不等于第三方可以获得完整输入。数据外部访问、公开发布和论文的数据可用性声明需各自真实证据；P03 不因双端保存自动关闭。
6. 本规范不改变原始数据、科学阈值、方法参数、预算、来源许可或历史判决。

## 8. 清理范围与异常处理

在已授权任务范围内，依照其清理合同处理明确的自产临时文件及核验后的冗余传输包；不把本规范解释为一次全盘清理授权。

- 清理前列明精确文件或目录，确认归属、保留副本、无活动进程依赖及无唯一信息。
- 删除或移动目录前，核对解析后的绝对路径仍在本轮允许范围内；不使用跨项目通配删除，不跟随链接误删保留副本。
- 不自动删除原始证据、唯一副本、用途不明文件、仍被读取入口依赖的文件或其他任务的产物。
- 不以“超过若干天”自动删除科研证据；保留期限有另行约定时遵从该约定。
- 发现损坏、来源不明、身份冲突或容量不足时，只暂停受影响步骤，保留可恢复状态并报告最小缺口；不擅自丢弃重要数组、降低精度或改研究设置。
- 本地不可逆清理、释放实例／数据盘等操作遵守现行授权边界，不在规范成文时自动执行。

## 9. 与当前研究资产的对应

以下是适用示例，不表示本次已检查其当前副本状态，也不要求现在移动或重新计算：

| 当前资产类型 | 适用规则 |
|---|---|
| 已完成 F_cov 接受终点、配置、读出和原评分 | 保留证据与昂贵缓存，不重新训练或读出来替代归档 |
| S23 轨迹、温度／导数数值缓存、接缝与参考评分所需输入 | 保留可复算内容；不为整理再次推进条件轨迹 |
| VO2 五工况两步长原生 `.npz` | 作为科研数组保留；后续分析输出与原始轨迹分开 |
| 封存协议与参考资料 | 延续原访问边界；备份清单不授予读取或评分权限 |
| 权威 Markdown 与最终 PDF／DOCX | 单一文本源构建；检查完成后可清理无用途的渲染缓存 |
| 独立复算包 | 保留完整输入、入口与实际能力说明；临时目录中的唯一副本需另行可靠归档 |

## 10. 每轮收口的简短执行清单

- [ ] 必要证据、接受态、配置、日志及终止原因已保存。
- [ ] 应双端保留的数据已核验；待同步及隔离例外如实列出。
- [ ] 原始与派生结果可区分，负面结果和科学信息边界完整。
- [ ] GPU 所需工作完成后的回收、关机按本轮合同落实；异常未虚报完成。
- [ ] 仅核验后的冗余传输包及不再依赖的临时文件进入清理范围。
- [ ] 没有覆盖冻结证据、删除唯一副本或改动无关任务文件。
- [ ] 交付记录明确区分保存、复制核验、独立复算与外部访问。

执行原则：**该保留的留足，该复用的直接复用，该删除的核验后删除；数据管理不得替代科研判断或扩大任务授权。**
